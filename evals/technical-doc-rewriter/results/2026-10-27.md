# Comparison run, 2026-10-27

## Method

- Fixtures: `fixtures/runbook-zh.md`, `fixtures/readme-en.md`, `fixtures/design-zh.md`.
- Two subagents on the same model rewrote each fixture once. The rewrites are in `2026-10-27/`.
  - `skill`: Loaded `skills/technical-doc-rewriter/SKILL.md` (then named `simplified-technical-writing`) and followed its workflow in the
    default tier, including `check.py` and `--compare`.
  - `baseline`: Got only this instruction, with one extra sentence that said "For the English
    document, apply the same instruction in simplified technical English; do not translate it."

    > 用简化技术中文（参照 ASD-STE100）改写这份文档：同一概念全文只用一个词；短句、主动句、写明主语；删掉“进行、加以”和“适当、显著、相关”这类空词；步骤用祈使句，条件和警告放在指令前面；只改措辞，不删任何事实、条件和风险，也不编数字。

- Score: `python3 grade.py 2026-10-27/skill 2026-10-27/baseline`. The assertions are in `README.md`
  and `cases.json`.

## Where the skill lost

- **design-zh.md, planned item (6.5).** The original says "已经支持按类目批量失效和热点 key 自动探测（预计
  2027 年 Q1）". The skill run kept the sentence and asked the author which part is done, because
  the guardrail "rewriting is not auditing" says to keep each claim as written. The baseline split
  the sentence into "已经支持按类目批量失效" and "热点缓存键自动探测预计在 2027 年 Q1 支持", and said
  that the split was its own reading. The baseline's reading matches the date in the original. The
  skill does not say what to do when the original itself marks part of a sentence as planned.
- **Convention findings.** The skill run kept `5~10分钟` and `为0` because the default tier keeps
  the document's own style. This is the intended behavior, but the output has 7 convention
  findings against 1 for the baseline.

## Where the skill won

- **runbook-zh.md, requirement words (3.4).** The baseline kept "必须" next to "应" and kept "最好".
  The skill run used one set (应 / 宜).
- **Author report.** The skill run listed claims without data, numbers without conditions and gaps
  in the content (for example, the rollback does not say what happens to data written to
  `order-db-2`). The baseline gave one line per file.

## Manual notes

- Both runs moved each warning before its step. Both changed the runbook's "注意" to "警告", which
  7.4 asks for.
- The skill run changed "一般小于 1 秒" to "在一般标准内：小于 1 秒". The meaning moved slightly.
- The baseline replaced "适当范围" with "正常范围". "正常" is as vague, and `check.py` does not
  report it.

## Limits of this run

- One rewrite for each arm and fixture. The result can change from run to run.
- The same scripts that the skill uses scored both runs, so the hard count favors the skill.
- The trigger cases in `trigger-cases.json` were not run. By hand against the `description`: the
  three positive cases name a rewrite or review of a technical document or STE / 受控语言 /
  简化技术中文, and the description excludes marketing posts, commit messages that nobody asked to
  rewrite, and translation.
